# 指标可行性清单

> 依据：本机对一台真实 TeslaMate v4.2 库（Model 3 RWD / 60 kWh LFP，2024-06 至今）逐条实测。
> 表里的耗时是 `EXPLAIN ANALYZE` 之外的端到端实测（含网络往返），不是估算。

## 一、取舍标准（三条，缺一不入选）

1. **能不能改变车主的一个决定** —— 充电时机、开法、要不要修、要不要卖。
2. **数据是否真的存在** —— 不看文档"应该有"，看库里有没有。
3. **页面成本能不能接受** —— 整页 < 300ms。任何要扫 `positions`（1300 万行）的指标默认出局。

## 二、入选（已实测，全部 ≤ 20ms）

### 充电行为

| 指标 | 数据来源 | 实测值 | 耗时 |
|---|---|---|---|
| 充电时段分布 | `charging_processes.start_date` | 傍晚(18 点后) 267 次 / 白天 110 / 深夜 99 —— 以「回家即插枪」为主 | 6ms |
| 终止 SoC 分布 | `end_battery_level` | **100% 占 74%**（373/501），<80% 只有 72 次 | 5ms |
| 平均功率 / 时长 | `charge_energy_added ÷ duration_min` | 22.2 kW / 176 分钟 | 3ms |

> 100% 占 74% 对 LFP 是**正确**的（官方建议每周至少一次充满）；换成三元锂车型这条要显示成警告。指标本身中性，解读随化学体系变。

## 三、明确不做（附实测理由）

| 指标 | 为什么不做 |
|---|---|
| **行驶能耗 Wh/km** | 「充电量 ÷ 里程」含充电损耗与驻车耗电，实测 279 Wh/km vs 车机额定 137，差一倍。要算准得积分 `positions.power`，而驻车时该字段是 ±14W 噪声（露营模式实测），算不出来。 |
| **驻车/露营耗电** | 同上。车停着时车机不上报功率，只能知道空调开着，不知道耗多少。 |
| **急加速 / 急刹次数** | 需要逐点加速度，1300 万行 `positions`。 |
| **停放掉电（%/天）** | 要按 3,662 个 `states` 区间逐个找前后 position，估计 3–8 秒。放页面太慢，为一月看一次的指标建物化视图不值。 |
| **地图热力图** | 需要瓦片服务或高德 key，违背「零配置开箱即用」。 |

## 五、后续可加（需要权衡，暂缓）

- **同比卡片**：今年 vs 去年同期（里程、电费、充电次数），数据现成，但会增加页面密度。
- **保养提醒**：按里程或时间推算（如「距上次保养 8,200 km」）——TeslaMate 没有保养记录，只能硬编码周期，而硬编码周期对开源项目是负担。
- **充电成本明细**：分时电价（TOU）已在库里，但只有配置过 `tou_rates` 才算得出，属于可选增强。
- **CO₂ 减排 / 相当于种树**：纯情绪价值，计算简单（km × 0.12 kg/km − 充电排放），但容易显得轻浮，等有用户要再加。
