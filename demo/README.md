# 前端样式 Demo · 评审说明

打开 `index.html` 即可。纯静态单文件，无构建、无 CDN、无外部依赖，断网也能看。

## 怎么评审

顶部有一条**评审工具条**（不属于产品 UI，正式版会去掉）：

| 操作 | 作用 |
|---|---|
| 手机 390 / 平板 820 / 桌面 1440 | 切换容器宽度，观察三档断点。**注意：布局靠容器查询（`@container`）判断，不看窗口宽度**，所以 1440 的窗口里也能真实模拟 390 手机 |
| 明 / 暗 | 切换主题，验证两套色板都成立 |
| 侧边栏 / 底部 Tab | 切换 概览 / 行程 / 充电 / 统计 四个页面 |

也可以用深链直接打开某一档某一页，方便截图对比：

```
index.html?vp=390&view=overview
index.html?vp=820&view=drives
index.html?vp=1440&view=insights&theme=light
```

> 数据全部是示意值（一台 Model Y 长续航、正在家充）。真机接的是 TeslaMate 的 PG + MQTT。

## 一、信息分层：为什么是这几张卡

判断标准只有一条：**这张卡的数据能不能改变车主当天的某个决定**（要不要现在充、车停哪了、这个月花了多少、电池是不是不行了）。按"打开频率"分三层，而不是按数据库表分。

### 第一层：每次打开都看（首屏，不做下钻就能得到答案）

| 卡片 | 数据来源 | 为什么值得占首屏 |
|---|---|---|
| 电量环 + 表显续航 | `positions.battery_level` / `est_battery_range_km` | 与特斯拉 App 对齐的"那一眼"，是最强肌肉记忆 |
| 状态胶囊（充电中/在线/休眠 N 分） | MQTT `state` / `since` | **解决"数字不动了是不是坏了"**。休眠期间数据本就停更，必须显式说出来 |
| 本次充电三数（已充/费用/电价） | `charging_processes` + `effective_cost()` | 国内车主对电费最敏感；分时电价是你库里已经算好的，不展示就浪费了 |
| 位置地图 | `positions` + `geofences`（GCJ-02） | 找车、确认停在哪层地库 |
| 4 个 KPI（今日里程/能耗/本月电费/电池健康） | `drives`、`positions` 日聚合 | 一眼扫完"今天用了多少、花了多少" |
| 最近行程 3 条 | `drives` + `addresses` | 最高频的回溯入口，必须首屏可达 |

### 第二层：每周看（第二屏，用于确认"一切正常"）

| 卡片 | 数据来源 | 价值 |
|---|---|---|
| 正在充电曲线（SOC 随时间） | `charging_processes` + `charges` | 判断充电是否正常、有没有在中途掉功率 |
| 近 14 天能耗 | `positions` 日聚合 | 能耗异常是轮胎/胎压/气温问题的最早信号 |
| 胎压四轮（含异常高亮） | MQTT `tpms_pressure_*` | 慢漏气不会报警但会持续掉，提前一周发现 |
| 行程列表 + 行程地图 | `drives` + `positions` | 报销、找"上周那趟"、看常跑路线 |

### 第三层：每月复盘（统计页，做别人没做的）

| 卡片 | 数据来源 | 为什么加它 |
|---|---|---|
| 月度能耗（12 个月） | `mv_daily` 物化视图 | 看出季节性：冬天 +25 Wh/km 是正常的，车主常误判为车坏了 |
| 电池健康曲线 | 满充续航/可用容量推算 | 直接回应"衰减焦虑"，比一个百分比更有说服力 |
| 本月省下的油钱 | `effective_cost()` vs 油价 | 情绪价值最高的一张卡，也是唯一会被截图分享的卡 |
| **停车掉电（吸血鬼耗电）** | `states` + `positions` 停放区间 | 车主社区最常抱怨的指标，Grafana 里要自己拼面板才能看 |
| 常去地点 Top4 | `geofences` + `drives` | 顺手，成本极低 |
| 电费构成（家充/超充）+ 时段分布 | `charging_processes` + TOU 表 | "谷电占比 78%" 直接对应省钱动作 |
| 更多看板（占位） | — | 演示扩展位：驾驶行为、时段热力图、哨兵事件、温度相关性 |

> **刻意没放的**：实时功率/电流/电压的原始曲线、每一次 GPS 点的列表、`update` 历史、车辆配置项。这些是"数据存在"但不是"车主想看"，属于 Grafana 深度分析台的职责，放进来只会稀释首屏。

## 二、视觉规则（这部分是"风格"的实质）

### 设计令牌

```
底色      #0A0E13   卡片 #141A22   卡片内嵌 #1A222C
描边      rgba(255,255,255,.07)，hover 时 .13
强调      #FF3B4E   特斯拉红，只用于"当前/激活/关键数字"
成功      #22C55E   充电中、良好
警告      #F59E0B   胎压、哨兵、偏低
信息      #4C8DFF   电池健康曲线
主文字    #F5F7FA   次级 #9AA4B2   三级 #6C7684
圆角      卡片 16–20px / 按钮 9–12px / 胶囊 999
间距      4 的倍数；卡片内 16–20；栅格间距 12–14
数字      font-variant-numeric: tabular-nums  ← 强制，否则实时数字会左右抖
```

### 三条比配色更重要的规则

1. **一屏只讲一件事。** 手机上首屏 = 车在哪 + 还剩多少电 + 在不在充电。其余全部塞进别的 Tab。Grafana 的病根就是把 20 个图表平铺，看的人抓不到重点。
2. **数值优先于图表。** 大号数字 + 单位 + 一句上下文（"优于年均 7%"）。图表放第二屏，用来解释数字，而不是代替数字。
3. **状态必须可解释。** "已休眠 42 分钟"比一个灰掉的数字有用一百倍。每个数据块都要能回答"这个值多久没更新了"。

### 状态色的语义（全局一致，不按页面变）

| 车辆状态 | 颜色 | 用在哪 |
|---|---|---|
| 充电中 | 绿 | 状态胶囊、SOC 环、充电卡 |
| 行驶中 | 蓝 | 状态胶囊、速度 |
| 在线（未充电） | 青 | 状态胶囊 |
| 休眠 | 灰 | 状态胶囊 + "已休眠 N 分钟" |

## 三、怎么扩展新看板（你的核心要求）

Demo 里的布局不是写死的，是这样组织的：

**1. 栅格：手机 2 列 → 平板 2 列 → 桌面 12 列**，卡片只声明"占几列"，不写像素。

```html
<article class="card c-half" style="--sp:4">  <!-- c-full / c-half / c-kpi -->
```

| 类 | 手机 | 平板 | 桌面 |
|---|---|---|---|
| `c-full` | 整行 | 整行 | `--sp` 列 |
| `c-half` | 整行 | 半行 | `--sp` 列 |
| `c-kpi` | 半行（2×2） | 半行（2×2） | `--sp` 列 |

新增一张卡 = 复制一段 `<article>`，改 `--sp` 和内容，**不需要动任何 CSS 断点**。

**2. 卡片注册表（正式版实现）**：每张卡在代码里声明元数据，列表页和布局都从注册表渲染，用户可拖动排序/隐藏：

```ts
{
  id: 'vampire_drain',
  title: '停车掉电',
  icon: 'temp',
  span: { mobile: 2, tablet: 1, desktop: 4 },
  priority: 'P2',
  visibleWhen: (live) => live.state === 'asleep',   // 只有停放时才出现
  query: 'stats.vampireDrain',                       // 对应后端一个接口
}
```

`visibleWhen` 是关键：**同一套卡片能长出两种首屏形态**——充电时首屏是充电卡，行驶时是行程卡，停放时是掉电/哨兵卡。不用做三套页面。

**3. 响应式靠容器查询，不靠 `@media`。** 每张卡只看"自己被放进了多宽的容器"。好处是同一份卡片能塞进侧边栏/widget/全屏三处，都不用改代码；也正好让这个 Demo 能在 1440 的窗口里真实模拟 390 手机。

## 四、待你确认的 5 件事

1. **首屏顺序**：现在是「车况 → 地图 → KPI → 充电 → 能耗 → 行程 → 胎压」。手机上你觉得地图应该在 KPI 之后吗？（地图放前面便于"找车"，放后面便于"看数"）
2. **多车支持**：你库里 `cars` 有 2 台。首屏要不要做车辆切换（顶部下拉 / 左右滑动）？如果两台车都常用，我会把 KPI 区改成可对比布局。
3. **行程回放**：行程详情要不要做时间轴拖动回放（速度/功率随位置变化）？这是工作量最大的一块，也最容易做出"哇"。
4. **亮色主题**：保留还是砍掉？保留的成本很低（令牌已双套），但暗色是主场景（夜间/车内）。
5. **驾驶行为评分**：数据算得出来（急加速/急刹/最高速），但评分标准主观，容易变成"没用的花活"。要不要？

确认后我按这个样式直接出 React + Tailwind + shadcn 的可运行版本（卡片注册表一并落地）。
